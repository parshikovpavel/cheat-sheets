# Gitlab CI

GitLab CI — это встроенная в GitLab система автоматизации сборки, проверки и доставки кода.

Обычно процесс выглядит так:

1. Разработчик отправляет изменения в GitLab.
2. GitLab читает файл `.gitlab-ci.yml`.
3. GitLab Runner запускает описанные в нём команды.
4. Формируется pipeline — последовательность автоматических проверок и действий.

Например:

```
stages:
  - test
  - build

unit-tests:
  stage: test
  script:
    - go test ./...

build:
  stage: build
  script:
    - go build ./cmd/app
```

Здесь pipeline состоит из двух стадий:

- `test` — запускает тесты;
- `build` — собирает приложение, если тесты прошли.

Основные понятия:

- **Pipeline** — полный процесс проверки и доставки одного изменения.
- **Stage** — этап, например `lint`, `test`, `build`, `deploy`.
- **Job** — конкретная задача внутри этапа.
- **Runner** — машина или контейнер, исполняющий команды.
- **Artifact** — результат job, например бинарник или отчёт о тестах.
- **Cache** — сохранённые зависимости для ускорения следующих запусков.

CI означает Continuous Integration — автоматическую проверку каждого изменения. Если pipeline также выкладывает приложение на стенд или в production, это уже часть CD — Continuous Delivery/Deployment.
