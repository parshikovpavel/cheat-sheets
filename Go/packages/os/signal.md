Package `signal` реализует доступ к входящим сигналам.

Сигналы в основном используются в системах, подобных Unix. 

#### Типы сигналов

Синхронные сигналы — это сигналы, вызываемые ошибками при выполнении программы: SIGBUS, SIGFPE и SIGSEGV. 

Остальные сигналы являются асинхронными. Они не вызываются ошибками программы, а отправляются ядром или какой-либо другой программой.

Сигнал SIGINT отправляется, когда пользователь на управляющем терминале нажимает символ прерывания, который по умолчанию равен ^C (Control-C). Сигнал SIGQUIT отправляется, когда пользователь на управляющем терминале нажимает символ выхода, который по умолчанию равен ^\ (Control-обратная косая черта). В общем случае, вы можете просто завершить работу программы, нажав ^C, а можете завершить её с дампом стека, нажав ^\\.

#### Стандартное поведение сигналов в программах на языке Go

По умолчанию синхронный сигнал преобразуется в панику во время выполнения. Сигналы SIGHUP, SIGINT или SIGTERM приводят к завершению программы. Сигналы SIGQUIT, SIGILL, SIGTRAP, SIGABRT, SIGSTKFLT, SIGEMT или SIGSYS приводят к завершению программы с дампом стека...

Если программа на Go запускается с непустой маской сигналов, она, как правило, будет соблюдена. ..

#### Изменение поведения сигналов в программах на языке Go

Функции этого пакета позволяют программе изменять способ обработки сигналов в программах Go.

Функция Notify отключает стандартное поведение для заданного набора асинхронных сигналов и вместо этого передает их по одному или нескольким зарегистрированным каналам. В частности, она применяется к сигналам SIGHUP, SIGINT, SIGQUIT, SIGABRT и SIGTERM. Она также применяется к сигналам управления заданиями SIGTSTP, SIGTTIN и SIGTTOU, в этом случае стандартное поведение системы не происходит. Она также применяется к некоторым сигналам, которые в противном случае не вызывают никаких действий: SIGUSR1, SIGUSR2,...

## Functions

### `func Notify()`

```go
func Notify(c chan<- os.Signal, sig ...os.Signal)
```

Функция `Notify()` заставляет *package* `signal` транслировать входящие сигналы в `c`. Если сигналы `sig` не указаны, все входящие сигналы будут транслированы в `c`. Иначе будут транслироваться только указанные сигналы `sig`.

Package `signal` не будет блокировать отправку в канал `c` , т.е. сигнал будет пропущен при отсутсвии места в канале: *caller* должен убедиться, что у канала `c` достаточно буферного пространства для обработки ожидаемой скорости передачи сигналов. Для канала, используемого для уведомления только об одном значении сигнала, достаточно буфера размером 1.

Допускается многократный вызов функции `Notify()` с одним и тем же каналом: каждый вызов расширяет набор сигналов, отправляемых в этот канал. Единственный способ удалить сигналы из набора — вызвать функцию `Stop()`.

Допускается многократный вызов функции `Notify()` с использованием разных каналов и одних и тех же сигналов: каждый канал получает копии входящих сигналов независимо.

Пример:

```go
import (
	"fmt"
	"os"
	"os/signal"
)

func main() {
  // Настройка канала для отправки уведомлений о сигналах. 
  // Необходимо использовать буферизованный канал, иначе есть риск пропустить сигнал,
  // если мы не будем готовы принять его в момент отправки.
	c := make(chan os.Signal, 1)
	signal.Notify(c, os.Interrupt)

	// Блокировать выполнение до получения сигнала.
	s := <-c
	fmt.Println("Got signal:", s)
}
```

Пример получения всех сигналов:

```go
package main

import (
	"fmt"
	"os"
	"os/signal"
)

func main() {
	/// Настройка канала для отправки уведомлений о сигналах. 
  // Необходимо использовать буферизованный канал, иначе есть риск пропустить сигнал,
  // если мы не будем готовы принять его в момент отправки.
	c := make(chan os.Signal, 1)

  // Если в Notify() не переданы сигналы, это означает,
  // что в канал будут отправляться все сигналы.
	signal.Notify(c)

	// Блокировать выполнение до получения сигнала.
	s := <-c
	fmt.Println("Got signal:", s)
}
```



### `func NotifyContext()`

```go
func NotifyContext(parent context.Context, signals ...os.Signal) (ctx context.Context, stop context.CancelFunc)
```

Функция `NotifyContext()` возвращает копию `parent` *context*, помеченную как *done* (ее канал `Done` *channel* закрыт), когда поступает один из перечисленных *signals*, когда вызывается возвращаемая `stop` *function* или когда закрывается `Done` *channel* *parent context*'а, в зависимости от того, что произойдет раньше.

Функция `stop` отменяет регистрацию поведения сигнала, что, подобно [`signal.Reset()`](https://pkg.go.dev/os/signal#Reset) , может восстановить поведение по умолчанию для данного сигнала. Например, поведение по умолчанию для программы на Go, получающей [`os.Interrupt`,](https://pkg.go.dev/os#Interrupt) — это завершение работы. Вызов `NotifyContext(parent, os.Interrupt)` изменит поведение на отмену возвращенного контекста `ctx`. Последующие прерывания не будут запускать поведение по умолчанию (завершение работы) до тех пор, пока не будет вызвана возвращенная функция `stop`.

Если сигнал приводит к отмене возвращенного контекста `ctx`, вызов [метода `context.Cause()`](https://pkg.go.dev/context#Cause) вернет ошибку, описывающую сигнал.

Функция `stop()` освобождает связанные с ней ресурсы, поэтому код должен вызывать `stop()`, как только операции, выполняемые в этом контексте, завершатся и сигналы больше не нужно будет перенаправлять в контекст.

```go
func main() {
	ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt)
	defer stop()

	<-ctx.Done()
}
```
